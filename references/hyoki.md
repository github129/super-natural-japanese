# 表記リファレンス

最優先は**文書内の統一**。どちらの表記が正しいかより、同じ語を同じ書き方で通すことが読みやすさに効く。プロジェクトに `.jp-style.txt` があれば、それが一般ルールより優先する。

## 1. 漢字とかなの使い分け（ビジネス・一般の既定）

かなで書く（漢字にすると硬く、読みにくい）：

- 補助動詞：〜していく、〜してみる、〜しておく、〜してしまう、〜してください、〜していただく、〜いたします
- 形式名詞：こと、とき、ところ、もの、ため、よう、わけ、はず
- 可能の「できる」（「出来」は名詞「出来が良い」だけ）
- 接続詞：ただし、なお、また、あるいは、したがって、しかし
- 常用漢字表にない字を使う語：ほとんど（殆ど）、あるいは（或いは）、まで（迄）、よろしく（宜しく）

本来の意味で使うときは漢字：「事が起きる」「約束の時」「物を運ぶ」「本社の所在地」「資料を下さい（本動詞）」

どちらでもよい語（混ぜないことだけ守る）：すべて／全て、さまざま／様々、さらに／更に、すでに／既に、たとえば／例えば、および／及び、または／又は

公用文では扱いが変わる語がある → `kouyoubun.md`

## 2. 数字

- 横書きは算用数字：3件、10人、2026年9月19日
- 慣用的な語・概数は漢数字：一般、一部、一時的、数十人、二、三日
- 4桁以上は位取りのコンマ：1,200円。大きな数は「万・億」を併用してよい：1億2,000万円
- 算用数字とアルファベットは半角。全角と半角を混ぜない

## 3. 記号

- 括弧は全角：（）「」『』。『』は書名か、「」の中の引用に使う。ただし既存文のリライトでは、括弧の全角半角やスラッシュは元のまま残す。揃えるのは「表記を統一して」と頼まれたときだけ(漢字とかなの使い分けは言い回しの範囲なので直してよい)
- 「！」「？」はビジネス文書では原則使わない。チャットでは可
- 句読点は「、。」が既定。「，．」を使う文書なら全体をそれで通す
- 英単語と日本語の間にスペースを入れるかどうかは、どちらかに統一する（「Slack で送る」／「Slackで送る」）

## 4. 外来語（カタカナ語）

- 語末の長音は付けるのが公的な原則（「外来語の表記」1991年）：サーバー、ユーザー、コンピューター、メモリー
- ただし IT 分野では「サーバ」「ユーザ」のように省く慣習も根強い。プロジェクトの慣習があればそちらを優先し、**文書内で混ぜない**
- 意味が通じにくいカタカナ語は日本語に：アジェンダ→議題、エビデンス→根拠、コンセンサス→合意、リスケ→日程変更

## 5. `.jp-style.txt` の書式

プロジェクトの表記ルールを1行1つで書く。`#` はコメント。区切りは `->`、`=>`、`→` のどれでもよい。

```
# 製品名・用語
ユーザ -> ユーザー
ログイン画面 -> サインイン画面
Github -> GitHub
# 社内の約束
致します -> いたします
```

`python3 scripts/check.py --rules .jp-style.txt <file>` で検出できる。
